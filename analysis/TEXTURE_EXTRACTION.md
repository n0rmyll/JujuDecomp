# GameCube texture extraction

`tools/decode_textures.py` exports base texture levels from the locally
extracted GJUE78 revision 0 assets. The first full pass scanned all 21 DBU
archives and 18 standalone DBL files to exact EOF using the existing chunk
parser. Standalone files use `GCN\0` at binary header +8 and big-endian chunk
fields. The wrapper allows precisely that observed signature while retaining
the original file SHA-256; the underlying DBU parser is unchanged.

## Executable evidence

Reports generated by `tools/function_report.py` verify every assembly
instruction against the expected main.dol bytes:

- Dispatcher `0x801B777C` routes types 0x82 and 0x86 to `0x8018BF18`.
- `0x8018BF18` reads the texture count from payload +0, starts records at
  payload +0x38, and advances records by 0x48 bytes.
- `0x8018BD78` relocates record offsets +0x04, +0x0C, and +0x1C relative to
  the payload base. The first is a linked record, the latter two are used
  for pixels and palettes by `0x80182F8C`.
- `0x80182F8C` reads dimensions at record +0x10/+0x12, the name at +0x28,
  and maps flags to GX texture/palette formats. It passes pixels from +0x0C
  and palettes from +0x1C to its runtime texture structure.

Observed format mapping follows that function:

| flags & 0x38 | flags & 7 | GX format |
| --- | --- | --- |
| 0 | 5 | CMPR |
| 0 | 2 | RGB565 |
| 8 or 0x28 | 0 | C4 |
| 8 or 0x28 | 1 | C8 |
| 0x18 | 2 | RGB5A3 |
| 0x18 | 4 | CMPR if flag 0x8000, otherwise RGBA8 |
| 0x10 | 1 | IA4 |
| 0x10 | 2 | IA8 |

Palettes use IA8 for mode 0x28; otherwise flag 0x8000 selects RGB565,
with RGB5A3 as the other observed case. Unknown flag combinations fail
explicitly. Block tiling, split RGBA8 planes, palette representations, and
GameCube CMPR interpolation were checked against Dolphin's
[generic texture decoder](https://github.com/dolphin-emu/dolphin/blob/master/Source/Core/VideoCommon/TextureDecoder_Generic.cpp)
and [CMPR interpolation helper](https://github.com/dolphin-emu/dolphin/blob/master/Source/Core/VideoCommon/TextureDecoder_Util.h).
The Python implementation uses no external packages.

## Results and limits

5,512 PNGs were written: 3,144 C8, 1,599 C4, 684 CMPR, 84 RGBA8,
and one RGB5A3. These counts retain repeated assets across level archives.
The manifest records source archive hashes, chunk and record indices,
absolute source byte offsets, path hints, and decoded RGBA hashes.
Disc-provided names are sanitized for output filenames; embedded paths are
metadata only.

Fifteen records have zero pixel offsets. Their names include waterfall,
dance-platform, feather, and charge textures with `_atx` suffixes. This
suggests an animated or externally supplied texture path, but its storage
and loading behavior have not been established. They remain explicit errors;
the exporter does not fabricate pixels or substitute nearby data.

Six independent tests cover RGBA channel planes and adjacent tile ordering,
C4 nibble ordering and transparent palette entries, CMPR quadrant ordering,
invalid ranges and unknown formats, original hashing for GCN headers, and
PNG scanline round-trip plus CRCs. Real controller icons and a chicken skin
were visually inspected. This does not establish correctness for every
texture, full GPU fidelity, or support for mipmaps/animated frames.

The generated gallery and all PNGs remain under ignored `assets/`.
Models, skeletal animation, material reconstruction, and audio conversion
are separate work still required.
